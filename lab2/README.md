Python 3.10 или новее. Дополнительные библиотеки не нужны.

## Запуск

Из корня репозитория:

```powershell
python lab2/main.py
```

Проверки:

```powershell
python -m unittest discover -s lab2 -v
```

## Устройство программы

```text
GameObject
├── Unit
│   └── Archer       + Attacker, Moveable
└── Building
    ├── Fort         + Attacker
    └── MobileHouse  + Moveable
```

- `game.py` — классы и интерфейсы.
- `main.py` — демонстрация создания, строительства, движения, атак и гибели.
- `test_game.py` — автоматические проверки поведения.

`GameObject`, `Unit` и `Building` — обычные классы: их данные и поведение
полностью определены. `Attacker` и `Moveable` — абстрактные классы с абстрактными
методами; они играют роль интерфейсов. Создать их экземпляр нельзя.
Дочерние классы обязаны реализовать соответствующие методы.

Имена методов из задания (`getId`, `getHp` и другие) сохранены.
Для `Moveable` выбран метод `move(x, y)`, задающий новые координаты:
в тексте задания его сигнатура не указана.

Идентификаторы автоматически выдаются общим счётчиком в пределах одного запуска.
Здоровье не опускается ниже нуля, отрицательный урон запрещён. Погибший лучник
не двигается и не атакует. Крепость и дом могут действовать после `build()`.
Эти правила выбраны для демонстрации; дальность атак, карта и очки хода
в этой работе не моделируются.

## Что объяснить на защите

- **Наследование:** `Archer` получает имя, координаты и здоровье от базовых классов.
- **Инкапсуляция:** состояние хранится в полях с `_`, доступ к нему идёт через
  методы. В Python `_` — соглашение о внутреннем использовании, а не запрет доступа.
- **Абстракция:** `Attacker` описывает способность атаковать без конкретной реализации.
- **Полиморфизм:** один вызов `attack(enemy)` работает и для лучника, и для крепости;
  пример находится в `main.py`.
- **Класс и объект:** `Archer` — описание, `archer` и `enemy` — его разные экземпляры.
- **Интерфейсы:** дом может двигаться, но не атаковать; крепость может атаковать,
  но не двигаться; лучник умеет и то и другое.
